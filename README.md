# Account Region Lab

本地多账号浏览器环境管理与地区观察工具。首版为每个账号保存独立的 Chrome / Edge 数据目录和固定代理，启动前检查代理出口国家，辅助记录 Google 服务条款中的账号关联国家及人工申请结果。

**它能帮助检查环境是否按计划运行，不能替 Google 决定账号关联国家，也没有实测证明使用一周能完成改区。** Google 的关联国家用于确定服务提供方、适用条款和地区要求，不适合作为可任意选择的账号用途标签。需要区分工作、个人或项目归属时，应使用本工具里的本地名称和备注。

## 首版能做什么

- 一个账号一个持久浏览器数据目录，保留该环境自己的 Cookie、登录状态和历史。
- 每个环境指定一个 HTTP 或 SOCKS5 代理，例如印度 `IN`、尼日利亚 `NG`。
- 每次启动前通过对应代理请求 `https://api.country.is/`，比对返回的 ISO 国家代码。检查失败或国家不符时拒绝启动。
- 打开原生 Chrome / Edge，由用户手工登录 Gmail、使用 YouTube 和查看 Google 官方地区页面。
- 保存七日观察记录、人工核查结果，并导出记录供自己比较。

首版不会自动观看视频、模拟正常用户行为、处理验证码、代填账号密码或自动提交改区申请。七日记录是观察周期，不是 Google 官方公布的改区资格或等待期。

## 运行

需要 Node.js 24、可用的 `curl` 命令，以及已安装的 Chrome 或 Edge。项目没有第三方 npm 依赖，无需执行 `npm install`。

在项目目录运行：

```bash
npm start
```

打开 <http://127.0.0.1:4317>。停止时在运行程序的终端按 `Ctrl+C`。

运行程序测试：

```bash
npm test
```

控制台仅用于本机。不要把该端口公开到公网，也不要把它作为多人共享的远程管理服务。

## 第一次使用

1. 首页已预置印度、尼日利亚两个未配置环境，也可以新建更多环境。名称可写成“印度项目 A”“尼日利亚资料”，**不用填写真实 Gmail 地址**。
2. 分别设置目标国家代码，例如 `IN` 和 `NG`，并填写自己已有的对应代理。
3. 启动环境。出口检查成功且国家匹配后，程序才会启动该环境的浏览器。
4. 在原生浏览器中手工登录。密码、通行密钥、两步验证和其他登录挑战都由浏览器及 Google 页面处理，不需要交给本工具或输入聊天窗口。
5. 在这个环境中打开 [Google 服务条款](https://policies.google.com/terms)，核对已登录账号的关联国家。将实际显示结果、检查时间和必要备注记入观察记录。
6. 后续始终从相应环境打开账号，正常完成自己的邮件、学习或工作。七天后比较记录；如关联国家与实际居住情况不符，可在该账号环境中打开 [Google 官方地区关联申请](https://policies.google.com/country-association-form)，阅读说明并按真实情况自行提交。

本工具不读取 Gmail 邮件正文，也不要求提供邮箱密码。浏览器登录信息留在对应浏览器数据目录中，不回传给本工具的控制台。浏览器访问 Google、代理连接及出口检查仍是正常的外部网络请求。

## 代理格式与检查的含义

支持不带用户名和密码的代理 URL：

```text
http://127.0.0.1:18081
socks5://127.0.0.1:18082
```

以上只是格式示例，必须替换为你实际配置的端点。每个环境应绑定所需的固定出口。

首版不支持 `http://用户名:密码@服务器:端口` 形式的带凭证 URL。如果上游代理需要认证，可以使用自己管理的本地转发，将认证留在转发程序中，再把不带凭证的本地端点填入本工具。

第一次成功发送浏览器启动请求后，环境会固定绑定目标国家和代理地址；名称仍可修改。需要换国家或代理地址时，请新建环境。这能避免复用仍在运行的浏览器进程时，检查了新代理、浏览器却仍使用旧代理的情况。代理服务本身的出口仍可能变化，因此每次启动都会重查。

启动前的检查只能证明：**当次 `curl` 请求通过该代理访问 country.is 时，country.is 返回了与目标相符的国家代码。** 它不证明 Google 使用相同的 IP 地理数据库，也不证明账号关联国家已经改变。

浏览器启动后可能遇到代理断连、网络切换、其他应用访问、DNS / WebRTC 等差异。首版没有系统级防火墙、全流量隧道或持续防泄漏保证。独立数据目录是浏览器会话隔离，不是完整虚拟机，也不能保证网站无法关联多个账号。

## 数据保存在何处

应用数据默认位于本机操作系统的用户应用数据目录下的 `AccountRegionLab`，在项目源码之外。Windows 通常位于 `%LOCALAPPDATA%\AccountRegionLab`。

浏览器 Profile 包含敏感登录会话，应像浏览器本身的用户数据一样保护。**不要把应用数据目录、Profile、Cookie 或导出的个人记录提交到 GitHub。** 删除或迁移数据前先关闭相应浏览器；不要让两个进程同时写同一个 Profile。

可通过环境变量调整：

| 变量 | 用途 |
| --- | --- |
| `REGION_LAB_DATA_DIR` | 指定应用数据保存目录，建议使用源码之外的绝对路径 |
| `BROWSER_PATH` | 指定 Chrome / Edge 可执行文件的绝对路径 |
| `PORT` | 调整本地控制台端口，默认 `4317` |

例如 Windows PowerShell：

```powershell
$env:REGION_LAB_DATA_DIR = 'D:\AccountRegionLabData'
$env:BROWSER_PATH = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
$env:PORT = '4317'
npm start
```

仅在实际路径存在且需要覆盖自动查找时设置 `BROWSER_PATH`。导出自动移除代理地址和检测 IP；环境名称和人工备注会保留，分享前请检查这些内容。

## 一周如何验收

把“工具是否工作”和“Google 是否改区”分开记录，避免把环境配置成功误记为账号改区成功。

| 时间 | 操作 | 可验收的结果 |
| --- | --- | --- |
| 第 0 天 | 建立印度、尼日利亚各一个环境；核查代理和账号当前关联国家 | 两个环境分别通过 `IN` / `NG` 检查；记录 Google 页面实际显示的初始国家 |
| 第 0 天 | 用专门的测试环境填入不匹配的目标国家，或不可用的代理，再启动 | 工具应报错并拒绝启动该测试环境；不要用真实账号做错误出口实验 |
| 第 1—6 天 | 正常手工使用；记录日期、出口结果、已核实的账号国家和异常 | 登录会话可在自己的环境中延续；不同账号没有因复用同一 Profile 串号 |
| 第 7 天 | 再次查看 Google 官方页面，并导出记录 | 分别报告环境是否稳定、Google 关联国家是否变化，不用“已满七天”代替观察结果 |
| 如需申诉 | 按官方页面说明、真实情况手工申请，记录提交时间和回复 | 以 Google 的实际回复及账号页面为准；未回复、拒绝、仍未变化均如实记录 |

观察记录是用户填写的本地日志，不是 Google 审核证据认证，也不能证明居住地。其他电脑、手机上的已登录会话仍可产生账号活动；本工具无法管理那些设备。

## 已知验证范围

`npm test` 只能验证程序中被测试的行为；出口检查成功只能验证该次外部请求。两者都不能验证 Google 的内部判定规则、申请结果或长期地区稳定性。

首版尚未完成真实 Gmail 账号的七日试验，没有验证印度或尼日利亚账号改区成功率。代理可用性、Google 登录挑战以及目标地区判定均需要在你的实际环境中观察。
